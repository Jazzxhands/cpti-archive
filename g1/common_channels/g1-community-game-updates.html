One little spoon (not beige) 3/15/2022 4:00 PM
Some quick tips: 1. the most basic and useful commands are add_units and remove_units, which let you specify color, system, and then a list of units to be placed in the system. 2. The format of unit list has you list each type of unit separately like 2 dn, 3 dd, 1 carrier etc. where units default to the space area, and if you want them on a planet you have to list them separately with the first letter of the relevant planet afterwards so to add a carrier with 2 fighters, 1 infantry in space and 1 on each abyz and fria you write: add_units purple abyzfria cv, 2 ff, inf, inf a, inf, f. 3. you don't have to have spaces after commas between units, but you do have to have spaces between numbers and unit type, so you can write the unit list in the above command cv,2 ff,inf,inf a,inf f but NOT cv,2ff,inf,inf a,inf f. 4. The move_units command is just a combination of remove_units and add_units and so the units you add don't have to match the units you are moving from. So if you need to move a carrier with two infantry and one of them is sacrificed to exploration, or another is produced by freelancers, you can just add it with the move_command. 5. The move command by default adds a command token of the relevant color to the destination system, unless you write NO in the optional field at the end of the command (you have to click tab several time or tap on it if you're on a phone). You can add a cc to a system that already has one of that color, it won't add another. 6. If you are moving units from several systems into one system, you can use the move command for one of the source systems, add all the units in the destination system and then use remove_units to remove units from the other origin systems. 7. Control tokens have to be added manually to planets and removed manually when you move out of them. If the system has only one planet you don't have to specify the planet name but if it has more, you need to specify in the optional field.
